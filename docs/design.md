# LogicLab — 逻辑电路沙盒 设计文档 v0.1（讨论稿）

> 状态：规格已收敛，尚未写游戏代码。本文档是后续开发的唯一蓝图。
> 工作名：LogicLab（可换）。第一版范围："先完全效仿图灵完备（Turing Complete）的沙盒玩法"。

---

## 0. 一句话规格

一个**桌面启动、游戏气质、工具品质**的逻辑电路沙盒：
从门电路一路搭到能算数的机器；目标是**数万门规模仍流畅**；**必须原生支持 ARM64 Windows**；
性能是唯一硬约束；UI 前期偏游戏、后期够专业；模拟语义以"和原版 TC 可对比验证"为质量线。

## 1. 已锁定的决策（来自三轮讨论问答）

| 维度 | 决策 |
|---|---|
| 定位 | 游戏向打底 + 专业工具品质线，前期重玩法 |
| 规模目标 | "类似 FPGA" = 大设计不卡（数万门流畅为验收尺） |
| 平台 | 桌面程序，游戏式启动；ARM64 Windows 必须能跑 |
| 技术栈 | Godot 4 当壳 + Rust 写芯（gdext 桥接）；core 纯库、确定性、可单测 |
| 时间模型 | **双模式可切换**：TC 式节拍单步 + 连续传播延迟（Digital/Logisim 风格） |
| 第一版范围 | 完全效仿 TC 沙盒玩法（组件种类与交互照做；美术资源自绘，不搬 TC 资产） |
| UI 风格 | 先快后美：第一版抽象浅色主题快速成型，后期可换皮（含暗色科幻向） |
| 行为验收 | 以原版 TC 为裁判：搭相同电路比对 gate / delay / tick 计分 |

## 2. 目标与非目标

**目标**
- 数万门设计平移缩放/运行/编辑均流畅（60fps 为基线，拖动不卡为体验红线）
- 双时间模型共享同一套 netlist 与事件引擎
- 确定性仿真：同输入序列 → 同结果（撤销/回放/自动验收的基石）
- core 与引擎解耦：Rust 纯库可脱离 Godot 跑单测与 benchmark
- ARM64 Windows 原生可运行（不只靠 x64 模拟）

**非目标（本期明确不做）**
- 不做 TC 的战役/RPG/关卡叙事（只做沙盒）
- 不搬运 TC 美术/音频/场景资产；一切视觉自绘
- 不做自定义元件封装的多层递归（后置，见组件清单）
- 不做 HDL 文本输入/综合（"FPGA"在此仅指规模野心）
- 不做云端/多人/创意工坊

## 3. 技术栈与理由

| 层 | 选型 | 理由 |
|---|---|---|
| 壳/UI | Godot 4（本机 4.7.2） | 游戏感（动效/音频/教学流）迭代最快；官方支持 Windows ARM64 |
| 核心 | Rust（纯 crate） | 性能 + 确定性 + 内存安全；cross 到 aarch64-pc-windows-msvc 一条命令 |
| 桥 | godot-rust gdext | 成熟、官方 asset；core 内部零 Godot 依赖，桥只做类型映射 |
| 存档 | 自研版本化格式 | core 编解码，UI 无关（见 §10） |

> ⚠️ ARM64 构建链为 **M0 里程碑的硬验证项**：确认 Godot 4.7 Windows ARM64 导出模板与 gdext
> 的 aarch64-pc-windows-msvc 目标可完整出包。若模板有缺口，fallback 是"编辑器 ARM64 原生 +
> 导出用模板覆盖/自托管模板"，这条要在写业务代码前钉死，避免后期返工。

## 4. 总体架构

```
┌─ Godot 4 壳（薄）────────────────────────────────┐
│ 画布：平移/缩放/网格/批量绘制（不走"每元件一节点"）     │
│ 交互：拖线/框选/撤销重做/元件库面板/属性检查器           │
│ 运行器：tick 模式 ↔ 连续时间模式（同一 core API）       │
└──────────────┬───────────────────────────────────┘
               │ gdext（薄桥：类型映射 + 对象生命周期）
┌──────────────▼───────────────────────────────────┐
│ Rust core（纯库，零 Godot 依赖）                    │
│  netlist 模型 · 离散事件引擎(双时间轴) · 值模型       │
│  0/1/X/Z+冲突 · 确定性调度 · 存档编解码 · undo 快照    │
│  unit tests + criterion benchmark（脱离引擎跑）      │
└──────────────────────────────────────────────────┘
```

### 4.1 分层职责
- **core/model**：元件/引脚/导线/端口定义，纯数据，可序列化
- **core/engine**：事件驱动调度器，不感知 UI
- **core/values**：0/1/X/Z + 多比特 + 冲突标记
- **bridge（gdext crate）**：把 core 状态映射成 Godot 可消费的结构（数组/字典），绝不放逻辑

### 4.1.1 桥接技术选型（M2 冒烟已验证，桥接已接通 core）
- **状态**：`bridge` crate（gdext）已把 `LogicLabCore` 类暴露给 Godot 4.7.2。
  实测 add_component / wire / set_input / tick / settle / take_dirty（增量同步）/
  component_info / component_pin 均可从 GDScript 调用，双向数据打通。
- **关键**：新增 `array <i64>/Dictionary<GString,Variant>` 泛型须显式书写（gdext v0.5）。
- **dirty 追踪**：core 的 Engine 已内置 `take_dirty()`——仿真后只搬运变化 pin，
  渲染层只重画 dirty 区域（性能铁律 #2 落地）。

### 4.1.1 桥接技术选型（M2 冒烟已验证）
- **选型**：godot-rust（gdext），git 依赖 `tag = "v0.5.5"`，crate 名 `godot`（包名 `godot`，workspace 子目录 `godot/`）。
- **已验证**：gdext v0.5.5 在 **Godot 4.7.2**（GUI/非 headless 模式）下初始化成功，
  `#[derive(GodotClass)]` 类可实例化、`#[func]` 可调用。**headless 模式不初始化 GDExtension**，
  加载测试必须用 GUI 模式（或 `--editor`）。
- **正确的最小类写法**：
  ```rust
  #[derive(GodotClass)]
  #[class(base = Node)]
  struct Foo;
  #[godot_api]
  impl INode for Foo { fn init(_b: Base<Node>) -> Self { Self } }
  #[gdextension(entry_symbol = my_entry)]
  unsafe impl ExtensionLibrary for Foo {}
  ```
  （`#[gdextension]` 宏生入口符号并自动注册所有 `#[derive(GodotClass)]` 类，无需手动 register。）
- **告诫**：`entry_symbol` 须为标识符（无引号）；.gdextension 的 `entry_symbol` 须与之匹配。

### 4.1.2 后端性能优化记录（M2 复查，已实测）
热点路径上所有"图省事的 clone/to_vec"已清除：

| 位置 | 优化前 | 优化后 |
|---|---|---|
| `Engine::settle()` | 每轮 clone 整个 pin_value 数组（≤128 次/调用） | 变化标志（`any_changed`），零分配 |
| `Engine::eval_component()` | 每元件 `component_pins().to_vec()` | 固定栈数组（≤8 pin），零堆分配 |
| `Engine::pin_bus()` | 每次调用 clone wire 列表 | 纯借用，零分配 |
| `merge_and_resolve/propagate/tick_once` | 各 2-3 个临时 Vec | 引擎持有 scratch 缓冲复用 |
| `Netlist::fanout_of` | clone + `contains` O(n²) + 分配 | `fanout_into` 复用缓冲 + 单 wire 快速路径 |
| `Pin.name: String` | 每引脚一次堆分配（且从未被读） | 字段删除 |
| dirty 追踪 | `HashSet<PinId>`（有哈希开销） | 标志数组 + 列表，O(1) 无哈希 |
| `pin_index_in_component` | `position()` 线性搜索 | `pin_slot` O(1) 减法 |
| **渲染层取值** | 每帧 O(n) 次跨 FFI + O(n) 次 Dictionary 分配 | **3 次批量快照**（components/pins/wires）+ 每帧 **1 次** `sync_dirty_values`（O(变化数)） |
| 死代码 | `debug_pin` / `Timed` / 重复的 `set_pin_internal` | 已删除 |

单测 13 → **17 个**（新增：缓冲复用不重分配、脏追踪增量性、引擎动态扩容、NOT 链收敛）。

### 4.1.3 单文件分发（自解压启动器）
GDExtension 的原生库**不能放进 pck**（Windows `LoadLibrary` 需要真实文件路径，且
`.gdextension` 在游戏代码执行前就被解析），所以带扩展的 Godot 游戏无法是"字面意义的单文件"。
本项目用**自解压启动器**把它封装成一个文件：

```
LogicLab-x64.exe = [launcher.exe][payload.zip][u64 LE payload 长度]
                              └─ LogicLab.exe + logiclab_bridge.dll + version.txt
```

- 首次运行：解压到 `%LOCALAPPDATA%\LogicLab\runtime`，然后启动游戏；
- 再次运行：读 `version.txt` 与 `.payload-stamp` 比对，命中则**跳过解压**（快速路径）；
- 打包：`pwsh -ExecutionPolicy Bypass -File tools\pack.ps1 -Arch x64|arm64`；
- 启动器同样是双架构编译（ARM64 包不含 x64 stub）。

产物：`dist/LogicLab-x64.exe`（55 MB）、`dist/LogicLab-arm64.exe`（47 MB）。

> 若将来要求"零解压的真单文件"，唯一路径是把 core 做成 **Godot 引擎模块**（把 Rust 以 C ABI
> 暴露、写 C++ module、从源码编译引擎并嵌入 pck）——代价大得多，暂不做。

### 4.2 架构铁律（防屎山 / 防卡顿，M2 起强制）
1. **渲染层零节点**：画布用单个自绘 `Control`/`Node2D` 批量绘制全部元件+导线
   （`draw_*` 单帧批量提交），禁止"每元件一个场景节点"。平移到小尺寸时降 LOD（元件→点、
   线束→线）。平移/缩放用节点变换矩阵，不逐个更新子节点。
   —— 这是 TC 卡顿的根因（每元件一节点 + 每帧全量重画），LogicLab 不从。
2. **增量同步，非全量快照**：bridge 只搬运"变化了的 pin 值"（dirty 集合），渲染层只重画
   dirty 区域。禁止每帧把整张 net 状态表全量拷贝到 Godot。
3. **编辑命令走 core**：用户在画布上的操作（拖线/摆元件/移动）作为命令发给 core，
   core 更新 netlist 并返回"哪些区域变了"，渲染层据此重画。undo/redo 由 core 命令树管理，
   保证仿真/编辑/渲染三份状态永远一致（不再像 TC 三头数据不同步）。

## 5. 核心数据模型（草案）

- **Netlist**：扁平表 + 索引（不用场景树节点表示电路）
  - components: id → kind + params + pins
  - wires: id → 端点集合（多叉）→ 网络（net）概念按连通性派生
  - 连续多引脚同 net：值合并 + 驱动冲突检测
- **值模型**：按专业工具走 0/1/X/Z，多比特为向量；冲突（多驱动不同值）显式标记并可着色
  - TC 的红/绿线判定 ≈ 我们的冲突标记策略，但要先定规则（见 §9 验收）
- **端口**：input/output/inout；位宽；类型（逻辑/时钟/数据）
- **确定性保证**：
  - 同 tick 内事件按稳定序处理（创建序/id 序，不许依赖哈希序）
  - 组合环收敛用固定迭代上限 + X/冲突判定（不做"碰运气"）
  - 无全局时间函数进仿真内核

## 6. 双时间模型（一个引擎，两个刻度）

**关键设计决定：不写两个仿真器。** 离散事件引擎 + 可插拔时间轴：

- **tick 模式（TC 风格）**：时间轴量化为整数 tick；元件 delay 属性 = 几 tick；
  组合传播以 tick 为单位结算；可单步/变速/连跑。输出 gate/delay/tick 计分（对齐 TC 评分轴）。
- **连续模式（专业工具）**：事件时间戳为浮点；延迟以"单位延迟"或显式 ns 配置实时流动；
  行为接近 Digital / Logisim 的传播。

两模式共享：netlist、元件语义（真值表/时序行为）、冲突检测、布线。差异只收敛在**调度器的时间推进与结算策略**上。
引擎内核接受一个 `TimeModel` trait；UI 侧只是一个开关。

## 7. 渲染与"数万门流畅"策略

性能的真正战场在渲染层（TC 卡顿的病根就是"每元件一节点 + 每帧全量重画"）。对策：

- **画布不建节点**：元件/导线用自定义 `_draw` + 批量提交（RenderingServer 单批次成片图元）
- **脏区/分块**：按视口裁剪 + 只重绘变化块；平移缩放用变换矩阵而非逐对象更新
- **LOD**：缩小到阈值以下时元件降级为点/占位，线束降级为单线
- **双缓冲状态**：编辑态（高保真）与运行态（高速仿真）分离，运行态只推增量
- 验收基线：≥50k 元件 + ≥100k 线段场景，平移/缩放/连线拖动不卡；benchmark 进 CI

## 8. 编辑交互功能清单（v0 完全效仿 TC 沙盒所需）

1. 画布：网格吸附、平移、缩放、框选、拖选
2. 摆放：从元件库拖/点选元件放置，旋转
3. 连线：从引脚拖线、正交绕行、分支、删线；TC 式"线头拖动"手感
4. 编辑：删除、复制/粘贴、undo/redo（core 快照 or 命令树，见 §11）
5. 元件库面板 + 属性检查器（引脚位宽/常量值/元件参数）
6. 运行控制：tick 单步 / 变速连跑 / 连续时间模式切换 / 复位
7. 探针与可视化：点选看值、线上流动动画（可关）、冲突着色
8. IO：开关/按键/常量作为输入；灯/七段/屏幕/扬声器作为输出（TC 沙盒那套）

## 9. 组件清单（v0，先效仿 TC，按依赖排序）

- **基础**：导线、常量、开关、按键、灯、七段、数码
- **门**：NOT/AND/OR/XOR/NAND/NOR/XNOR（含多输入与位宽）
- **算术/逻辑位宽**：加/减/比较/移位/MUX/DEMUX/译码（BYTE/WORD/DWORD 位宽族）
- **时序**：DFF/寄存器/计数器（TC 语义：显式时钟、边沿、tick 预算）
- **存储**：RAM/ROM（先定读写时序与初始化语义）
- **自定义元件**：后置里程碑（TC 的 component factory 递归展开是最重的一块）
- 其余 TC 冷门组件（电平检测、探针位等）按"核心对齐、边角自定"原则

> 每条组件的语义（真值/延迟/边沿/冲突）都要落到"行为用例"里，见 §10 验收。

## 10. 行为验收方法（以原版 TC 为裁判）

- 你在原版 TC 沙盒里搭一组**黄金基准电路**（RS 锁存、DFF 链、时钟分频、故意总线竞争…），
  记录每例的 gate/delay/tick 与行为；
- 同一电路在我们沙盒复现，比对结果；
- 这些用例同时进 core 的集成测试（golden circuits as fixtures），每次改动跑一遍；
- 语义优先级：关键规则（tick 结算/延迟传播/竞争判定/DFF 边沿）严格对齐；边角组件可自定。
- 产出物：`docs/golden_circuits/` 每个用例 = 电路存档 + 期望值表（gate/delay/tick/波形）

## 11. 存档格式设计（讨论稿，写码前再定稿）

- 版本化头 + 正文；核心诉求：**确定性、可 diff、前后兼容**
- 草案方向：
  - 第一版用有结构的文本（JSON 或 Godot 无关的自定义文本），可读可 diff，便于开发期调试；
  - 性能瓶颈不在存档，不值得上来就做二进制打包；后期需要再出 v2 二进制
- 内容：元件表（kind/params/pins）、导线拓扑、视图状态（相机/缩放/选中，UI 元数据隔离）、
  用户设置；TC 的 progress/levels 概念本期不需要（无战役）
- 断言的"落盘=读回=原样"往返测试进 core

## 16. 对齐 v3 规格：core 重写记录

### 16.1 为什么必须重写引擎

原引擎是"组合逻辑迭代到定点（settle）"模型，与 v3 §5.1 / ADR-1 要求的
**"所有组件输出一律延迟 1 tick + 双缓冲原子提交"根本冲突**。
规格要求架构在 M0 一次定死，所以整体重写了 core 的数据层与引擎。

新模型反而更快：去掉定点迭代后，一个 tick 就是"读旧值 → 求值 → 提交"一趟。

```text
tick():
  阶段 A  对每个脏组件，用【本拍开始时的网值】求值 → 写入暂存区
  阶段 B  原子提交暂存区 → 网络值，记录变化的网络
  阶段 C  tick += 1（下一拍的脏集合由本拍变化的网络推出）
```

### 16.2 core 模块划分（单一职责）

| 模块 | 职责 |
|---|---|
| `values` | 位宽 {1,4,8,16,32}、位级未知标记、wrap 算术（ADR-4 / ADR-22） |
| `defs` | **组件知识的唯一数据源**：DefId / Params / PinDef / eval。UI 元件库也从此读，不再两处硬编码 |
| `board` | 编辑期模型（Board = 实例 + 导线）、网表推导、自动走线 |
| `engine` | 双缓冲 tick、脏传播、CSR 邻接 |

**铁律**：core 依赖树中不得出现任何 godot 类型（ADR-21）。

### 16.3 三个关键算法决策

1. **网表推导 = 行 / 列区间合并 + 二分**
   性质：同一直线上两条正交线段只要区间相交就必然连接（相交时总有一方的端点落在对方上）。
   于是可先把相交区间合并成互不相交的集合，点查询只需一次二分。
   复杂度 O((W+P)·log n)，取代原先的 O(W²)——星形布线与长总线都不再退化。
   实测：万级导线电路的网表推导从 **71 s 降到 6.7 ms**。

2. **自动走线 = 受限网格 Dijkstra**
   状态为 (格点, 进入方向)，转弯有代价（少拐弯更好读）。
   禁止通行的只有两类：落入引脚 / 导线端点的格点、与已有导线**真重叠**的边。
   **十字穿越是允许的**（ADR-7）。搜索区域限制在两端点包围盒外扩 16 格内。

3. **折线只保留端点与拐点**
   不只是紧凑——若把路径上每个格点都当顶点，后续走线会被前面线自己的路径堵死，
   最后退化成会误连的兜底折线。这是正确性问题，不是美观问题。

### 16.4 实测（release 构建）

| 指标 | 数值 | 规格要求 |
|---|---|---|
| 10000 元件（10001 组件）每拍仿真 | **0.475 ms** | < 5 ms ✅ |
| 万级电路网表推导 + 装载 | 6.7 ms | — |
| 静默电路每拍求值组件数 | 0 | 事件驱动生效 ✅ |
| core 单元测试 | 51 项全绿 | — |

### 16.5 语义细节钉死（本轮新增）

- **Clock**：上电输出低，低 `low` 拍后翻高、持续 `high` 拍（§5.2"初相 0"的落地口径）
- **DFF / Register / Counter**：`reset` 优先于时钟锁存；沿在 t 被读到，输出 t+1 出现（ADR-1 / ADR-3）
- **悬空引脚**：输出引脚分配私有网络（值必须可读，探针 / 波形 / 测试都要）；
  输入引脚无网络，读作 0（ADR-5）

### 16.6 已观察到、且符合预期的"怪"行为（不是 bug）

对称初态（上电全 0）下，NOR 交叉耦合锁存器与奇数级反相环会**自持振荡**：
三级反相环实测**周期 2**（全网同步翻转），而不是"信号沿环路走一圈"的周期 6。
规格 §5.1 明确允许并要求 UI 给警告而非阻止——**振荡检测列入 M2 待办**。

## 17. 精简与「去 Godot」准备

### 17.1 已完成的结构性解耦

| 动作 | 意义 |
|---|---|
| 新增 `cli` crate（headless） | **core 能脱离 Godot 独立运行的证明**——其依赖树里没有任何引擎类型（ADR-21 / §15 验收 #6） |
| 建立 workspace（core + cli + launcher，bridge 排除） | 日常 `cargo test` 完全不需要 Godot、不需要联网拉 gdext |
| `save` 模块（工程 JSON） | core 只做 `&str ↔ 结构`，落盘归壳层/CLI；这是"换壳时 core 一行不改"的前提 |
| core 的 `bin/demo.rs` 移入 cli | core 回归纯库 |

### 17.2 体积账

已做的清理：

- 中文字体从 5 个字重精简到 1 个（Bold 从未被引用、Medium 声明了却没使用、拉丁字体无人引用）
- **导出产物 122.1 MB → 110.1 MB（-12 MB）**
- 清掉 `bridge/target` 等构建缓存约 **2.6 GB** 磁盘

进一步的两条路线：

| 路线 | 预期单文件 | 成本 |
|---|---|---|
| 现状 | 55 MB | — |
| 自编译裁剪 Godot 引擎（关掉 3D / 物理 / 导航 / XR / 多人等模块） | ~25 MB | 需要 scons + Python + MSVC，两个架构各编一次；以后升级 Godot 要重编 |
| 换纯 Rust 壳（winit + 自绘 UI） | ~5–10 MB | 要重写全部 UI 层，但 core / cli 原样带走 |

判断：**先不折腾体积**。引擎裁剪是"维护负担换体积"，换壳是"工期换体积"，
而体积目前不是硬指标（硬指标是性能）。等 M2 功能成形再评估。

### 17.3 换壳的关键准备：壳无关的视图模型（下一步）

现在渲染所需的数据由 bridge 现算，返回的是 Godot 的 `PackedInt64Array`；
换壳时这部分要整个重写。更好的做法是在 core 里定义**壳无关的呈现数据**：

```rust
// core/src/view.rs —— 只描述电路的几何与电学状态，不含任何 UI 框架语义
pub struct CircuitView {
    pub components: Vec<ComponentView>,  // 位置 / 尺寸 / 标签 / 选中
    pub pins: Vec<PinView>,              // 位置 / 方向 / 位宽 / 当前值
    pub wires: Vec<WireView>,            // 折线 / 当前值 / 连通状态
}
```

判断依据：它不知道按钮、主题、字体，因此不违反 ADR-21 的"core 不碰 UI 概念"，
却能把换壳成本压到"只写一个消费 CircuitView 的渲染器"。

### 17.4 从原版 TC 借鉴到的结论（只借鉴机制，遵守 §17 版权红线）

反编译其脚本后确认（仅用于理解机制，不取任何代码 / 素材 / 文案）：

| 观察 | 对我们的意义 |
|---|---|
| TC 是**每引脚一个 Sprite 节点**（逐个 `get_child(i).texture = ...`） | 印证架构法则 #1 的正确性：万级元件下节点数会爆。我们自绘正是为此而生 |
| `wire.gd` 状态机：`NORMAL / DISCONNECTED / SHORT_CIRCUIT / COORCED_0 / CIRCULAR_DEPENDENCY` | TC 确实检测**组合环**与**短路**；我们的 DRC 要对齐这几类 |
| `raw_path / render_path / drone_path` + `drones` | 这就是 §1 说的"信号沿导线涟漪传播"动画的实现方式，渲染层创意，M3 可做 |
| 位宽 `{1,8,16,32,64}`、`z_states`（三态）、`bidirectional` 引脚、导线 `delay` + `delay_critical_path` | 三态/双向已在 P1、关键路径在 §9.5 规划；位宽按规格保持 `{1,4,8,16,32}` |
| 组件清单另有 DelayLine / LatencyRam / FastRam / Hdd / SegmentDisplay / ProgramWord / Halt | 我们的组件集覆盖了基础部分，外设类已在 §6.6 规划 |

## 19. Beta 2

### 19.1 新增

**1. 设计规则检查（`core/src/drc.rs`）**

规格要求 DRC 必须先于 Verilog 导出落地。本期实现四类：

| 检查项 | 级别 | 判定 |
|---|---|---|
| 多驱动 | 错误 | 同一网络上有 > 1 个输出驱动 |
| 位宽不匹配 | 错误 | ADR-6：禁止隐式拆合，必须走 Splitter / Merger |
| 悬空输入 | 警告 | ADR-5：读作 0，但应当提示 |
| 组合环 | 错误 | 对组件级有向图求强连通分量；分量内**全是组合组件**才算环 |

反馈本身合法（只要环上有时序元件）——这正是锁存器与寄存器的用法，
所以判据是"环上有没有时序元件"，而不是"有没有环"。

**2. 参数知识进 core**

新增 `DefId::params() -> &[ParamDesc]`：每个组件可编辑哪些参数、控件是什么类型、
取值范围多大，全部由 core 描述。UI 只是**照着描述生成控件**，壳里不再有
"哪个组件能改什么"的硬编码。加新组件时只改 core 一处。

**3. 内置示例电路（`core/src/examples.rs`）**

半加器 / NAND 锁存器 / 三级移位寄存器 / 4 位计数器 / 2 选 1 MUX。
既是用户的起点，也是自测夹具——测试会验证每个示例都能建成、都能自动走通、且无 DRC 错误。

顺带得到一个有意思的结论：**SR 锁存器会被 DRC 报组合环，这是正确行为**
（它就是纯组合反馈，导出 Verilog 会失败）。测试里为此显式列了豁免名单，
并另加一条测试确认"它确实会被抓出来"，免得豁免把检查也一起关掉了。

**4. 界面**

- 示例下拉：一键载入能跑的电路
- 参数面板改为按 core 的描述动态生成（时钟周期、RAM 深度、有符号比较、使能/复位/进位脚…）
- "设计规则检查"按钮：摘要常驻 + 明细弹窗
- 启动即载入半加器示例，打开就能看到东西
