## 0. 定位与范围

**一句话定位**：比图灵完备专业、比 Vivado/Quartus 入门的数字电路设计 + 仿真 + 验证工具，带游戏化的即时反馈体验。

**目标用户**：DIY 硬件玩家、数电初学者、想在上 FPGA 板 / 买开发板之前先在软件里练手的人。

**核心要实现的四件事**：
1. tick 制电路仿真引擎（TC 的精髓）
2. 自由搭建 + 层次化封装的电路编辑器（TC 沙盒的精髓）
3. 专业化四件套：**可观测**（波形/VCD）、**可验证**（测试台）、**可迁移**（Verilog 导出）、**可上板**（预留引脚绑定）
4. 造机玩法：用户可在沙盒内自建 CPU + 自定义指令集 + 汇编编程（可选但推荐）

**明确不做（相对 TC 砍掉的部分）**：
- ❌ 剧情线（外星人故事等）
- ❌ 章节制关卡、解锁进度（Crude Awakening → NOT Gate → … 全部删除）
- ❌ GATE / DELAY / TICK 三维计分与排行榜
- ❌ 成就系统
- ✅ 取代解锁机制：**组件库开箱全量开放**（这是与 TC 最大的结构差异，见 §6 开头说明）

## 1. 核心循环（沙盒模式）

```
新建工程 → 放组件 / 拉导线 → 实时仿真（可暂停/单步/调速）
        → 探针 + 波形观察 → 调试修改（编辑生效即重置仿真，ADR-23）
        → 封装为自定义组件 → 复用/搭建更大系统
        → 写测试向量做回归验证
        → checkpoint 快照 → 快速回放长程序
        → 导出 Verilog / VCD 离线使用
```

游戏感来自：信号沿导线逐 tick "涟漪"传播的实时可视化、从门电路一路封装出整台 CPU 的成长感、以及自建 CPU 跑自己汇编程序的成就感。**不靠关卡，靠即时反馈和创造感。**

## 2. 从 TC 沙盒继承的核心逻辑（及设计理由）

以下机制是 TC 被验证过、必须原样继承的部分：

| 机制 | TC 的做法 | 为什么保留 |
|---|---|---|
| **tick 制离散仿真** | 全局 tick 计数器驱动，所有组件输出统一延迟 1 tick | 反馈环路（锁存器）天然合法，无需事件队列/静态求解，实现简单且行为可预期 |
| **1 tick 门延迟** | t tick 输出 = f(t-1 tick 输入)，导线零延迟 | 信号传播过程可见，门延迟不再是抽象概念——这是教学价值的核心，不是 bug |
| **双缓冲更新** | 全部组件先算入暂存区，再原子提交 | 避免 tick 内更新顺序依赖，结果确定可复现 |
| **渐进封装** | 任意电路可"另存为组件"，递归实例化 | 层次化设计 = 真实芯片开发的核心思维，也是从门到 CPU 的唯一可行路径 |
| **简单信号模型** | 二值信号（0/1），位宽分 1 位与字节 | 起步门槛低（本版升级为参数化位宽，见 §4） |
| **多驱动禁止** | 两个输出接同一网络在编辑期即拦截 | 强制用户学 MUX/三态，与真实电路约束一致 |

**与 TC 的关键差异**（本项目的决策）：
1. 无解锁：组件全量可用（TC 靠关卡把"你的解法"变成组件，本项目直接给官方组件库，同时允许用户自建同名组件覆盖）。
2. 专业化：波形、测试台、Verilog 导出、DRC 是一等公民（TC 完全没有）。
3. **层级可调试**：探针/波形/测试断言可指向任意嵌套层级的 Net（ADR-25，TC 做不到只能进入组件看）。

## 3. 系统架构（Godot + Rust，总纲）

### 3.1 分层原则：core 与壳彻底分离

```
┌─────────────────────────────────────────────┐
│  Godot 4（壳）                               │
│  编辑器 UI / 渲染 / 外设展示 / 事件捕获        │
│  gdext (godot-rust) GDExtension              │
├─────────────────────────────────────────────┤
│  Rust core（纯 Rust 库，零 Godot 依赖）        │
│  model:   数据模型 / 序列化 / netlist 推导     │
│  sim:     tick 仿真引擎（双缓冲 + 脏标记）     │
│  driver:  命令栈（undo/redo）/ 仿真状态管理    │
│  check:   DRC / 关键路径                      │
│  verify:  测试台执行器 / 波形记录 / checkpoint │
│  export:  Verilog 导出·VCD 导出（独立 crate 亦可）│
│  asm:     ISA 定义解析 / 汇编器               │
├─────────────────────────────────────────────┤
│  CLI（headless，依赖 core 不依赖 Godot）       │
│  批量回归 / 快进仿真 / CI                     │
└─────────────────────────────────────────────┘
```

**铁律：core crate 及其依赖树中禁止出现任何 godot 类型。** 这是"未来脱离 Godot"的唯一保证。CI 强制：`cargo check -p core -p cli` 独立编译必须通过。将来换壳（egui / Tauri / Bevy）时 core 一行不改。

core 内部按模块分层（model / sim / driver / check / verify / export / asm）；若模块边界清晰，可在 workspace 中拆为独立 crate（见下表），拆与不拆以"编译边界可单独 check"为准。

### 3.2 crate 划分

| crate | 内容 | 依赖 |
|---|---|---|
| `core` | model + sim + driver + check + verify | 无（仅 serde 等基础库） |
| `export-verilog` | netlist → Verilog 翻译器 | core |
| `asm` | ISA 定义解析（JSON）、汇编器、反汇编器 | core（或独立） |
| `godot-shell` | GDExtension：把 core 包成 Godot 类，桥接 UI | core, gdext |
| `cli` | headless：跑测试向量、快进仿真、批量导出 | core, export-verilog, asm |

### 3.3 数据流与线程模型

**命令（UI → core，同步调用）**：
```
UI 事件 → shell 转成 core 命令（AddInstance / AddWire / SetInput / Tick / …）
        → core 应用命令并返回结果 + 脏标记
```

**状态（core → UI，快照 + 脏事件）**：
```
每个 tick 后 core 累积 NetValueChange 列表（哪个 net 从什么值变成什么值）
shell 每帧拉取一次，应用到渲染（导线重绘、探针刷新、波形追加）
```
UI 永远只读快照，不持有仿真状态——解耦的关键。

**仿真驱动（分阶段）**：
- **M1~M2（单线程够用）**：Godot `_process` 里累加器模式：
  ```
  acc += delta
  while acc >= tick_dt && executed < max_ticks_per_frame:
      core.tick(); acc -= tick_dt
  ```
  `tick_dt` 由调速档位决定（暂停=∞，单步=手动触发，1~200 tick/s 正常档）；`max_ticks_per_frame` 防低帧率雪崩（默认 = max(1, tick_rate/60)×2）。**不要用 Godot 物理帧驱动。**
- **M3+（超速/长程序）**：core 提供 `run_for(n_ticks) -> Summary` headless 快进 API，在工作线程执行，channel 回传周期性快照；UI 显示"已执行 N tick"。跑百万 tick 的 CPU 程序靠这个，不靠 UI 硬刷。

**输入组件（Button/Switch/Keyboard）**：UI 事件 → `core.set_input(instance, value)`，下一 tick 生效。

### 3.4 脱离 Godot 的路径（写进架构，不是口头承诺）

core 不碰文件系统（JSON 以 `&str`/`&[u8]` 进出，文件读写是 shell 和 cli 的职责）、不碰时钟（tick 由外部驱动）、不碰 UI 概念。满足这三条，换壳 = 重写一个 shell crate，core 与 cli 原样带走。

## 4. 数据模型

```
SignalType:  位宽 ∈ {1, 4, 8, 16, 32}，可选 signed/unsigned（仅影响显示与比较器/ALU 语义）

ComponentDef（组件定义）
  id, name, 尺寸(格), 分类
  inputs[] / outputs[]: Pin { name, 相对坐标, 位宽 }
  behavior: 内置纯函数 | circuit: Board（用户自定义组件）
  delay（仅内置组件）: 传播延迟，恒 1 tick
  【v4 修正】用户自定义组件**没有独立 delay 字段**：
    其延迟 = 内部电路最长 acyclic 组合路径长度（tick 单位），
    由引擎在网表构建时推导；关键路径报告（§9.5）依此计算。
    内置复合组件（如 8 位加法器）依然 1 tick——
    因此用户手搓电路天然比内置慢（TC 同款涌现特性，是教学点不是缺陷）

ComponentInstance（板上实例）
  uuid, defId, x, y, rotation ∈ {0,90,180,270}, 参数(位宽/初始值等)
  display_name: 默认自动命名 inst_<n>（可改），层级调试路径（ADR-25）与
    Verilog 导出的实例名均基于此

Wire
  多段折线（正交 + 45°），端点挂在 Pin 或线路交汇点上
  连接判定（钉死，见 ADR-7）：端点落在另一条线上或线端点上 = 连接；
    纯交叉不连接；连接点渲染为实心圆（junction）

Board（电路板/图纸）
  instances[] + wires[] + netLabels[] + annotations[]（文本注释，见 ADR-23bis 与 §8）
  → netlist（由引擎从图推导）

工程（Project，单 JSON 文件，自包含）
  schema_version, boards, 自定义组件定义, 测试向量集,
  波形观察配置, 仿真配置(调速/暂停状态不入档)
  迁移策略：schema_version + 链式迁移函数，老版本工程打开时逐级升格

嵌套封装：任意 Board 可"另存为组件"递归实例化；
保存时做可达性检查，禁止包含自身引用（防无限递归）。
```

**坐标系**：整数格（1 格 = 8px 渲染单位，仅渲染层换算）；组件原点左上角，rotation 变换 pin 相对坐标。逻辑层禁止浮点（ADR-22）。

## 5. 仿真引擎（最核心）

### 5.1 基本规则

- **离散 tick 驱动**。全局 tick 计数器；暂停 / 单步 / 调速（1 ~ 200 tick/s 常规档，headless 无上限）。
- **所有组件输出延迟 1 tick**：t tick 的输出 = f(t-1 tick 的输入)。内置组件一律 1 tick；用户组件延迟涌现（见 §4 ComponentDef）。导线/Net 零延迟、同 tick 传播。
- **两阶段更新（双缓冲）**：
  ```
  tick():
      for comp in dirty_components:          # 事件驱动优化
          ins = [net[p] for p in comp.inputs]   # 读当前网值
          outs = comp.eval(ins, comp.state)     # 纯函数
          staging[comp] = outs
      commit staging → nets（原子提交）          # 全部算完一起翻转
      tick_count += 1
  ```
- **反馈环路合法**：SR 锁存器、环形振荡器都能跑。检测到固定周期振荡时 UI 警告（不阻止）。
- **边沿触发**：寄存器/触发器组件内部保存上一 tick 的 clock 值，`prev==0 && cur==1` 且 enable=1 时锁存输入。**必须用 prev_tick 快照实现，不能在 eval 里就地改状态**。
- **未连接输入 = 0**（渲染为灰色）。**多驱动冲突在编辑期拦截**（DRC，见 §9.5）。
- **确定性（不变量）**：同电路 + 同外部输入时间表 → 逐 tick 完全可复现；组件实例的遍历顺序不影响结果（双缓冲保证，见 §14 测试）。
- **编辑即重置（ADR-23）**：任何编辑命令（含 undo/redo）生效后，仿真状态整体重置到上电态并清空波形缓冲；编辑不强制要求暂停。
- **性能要求（硬指标）**：事件驱动 + 脏标记（输入未变的组件跳过 eval）。万级元件下每 tick < 5ms（stretch：十万元件）。对标：hneemann/Digital 的示例处理器可跑 120kHz。

### 5.2 语义钉死（模糊点全部消除）

| 语义 | 钉死 |
|---|---|
| 上电初始状态 | 全部时序元件输出 0；RAM 支持 preload（初始内容存工程） |
| 复位 | 触发器/计数器带可选 async reset 引脚；reset=1 时**优先于**时钟锁存，效果下一 tick 生效（tick 模型下"异步"即"不等时钟沿"） |
| 算术溢出 | 一律 wrap（补码回绕），无异常无饱和 |
| 多位 net 部分位无驱动 | 该位 = 0（"悬空即 0"推广到位级） |
| 位宽不匹配连接 | **禁止**（DRC 拦截）；1↔多位必须走 Splitter/Merger，不允许隐式拆合 |
| 多时钟域 | 允许多个 Clock 组件（TC 同款玩法）；DRC 对"时序元件 clock 引脚接了逻辑输出"给**警告**不报错；跨时钟域数据不做 CDC 检查（玩家自负） |
| Clock 组件 | 初相 0，可配高 N tick 低 M tick；上电第一个翻转在 N tick 后 |
| 组件延迟 | 内置恒 1 tick；用户组件 = 内部最长组合路径（涌现值，引擎推导不手填） |
| 编辑与仿真 | 编辑生效 → 仿真重置上电态 + 清空波形（ADR-23） |

## 6. 组件库（全量开放，开箱即用）

> 说明：TC 用关卡解锁组件（你的 NOT 门解法就是你的 NOT 组件）。本项目无关卡，故官方库全量提供；用户仍可自建组件，同名时可选择覆盖官方版（记录在工程里，导出时以工程内定义为准）。

### 6.1 输入 / 输出
| 组件 | 说明 |
|---|---|
| Button | 按住为 1 |
| Switch | 点击切换 0/1 |
| Clock | 周期可配的时钟源 |
| Constant | 参数化位宽的常量（值可编辑） |
| LED / 探针 | 显示位值；多位于 16 进制 / 10 进制（可切 signed/unsigned） |

### 6.2 逻辑门（输入数 2~8 可参数化）
NOT、AND、OR、NAND、NOR、XOR、XNOR、Buffer

### 6.3 多位 / 选择
Splitter / Merger：**任意两段位宽组合**（如 8↔4+4、16↔8+8、32↔16+16），不限于↔1位；MUX（2/4/8 选 1）、译码器、优先编码器

### 6.4 算术
半加器、全加器、加减法器（可选进位输入/输出）、乘法器、除法器（可选）、比较器（EQ / LT 有符号 / LTU 无符号）、移位器（左/右/算术右移）、可配置 ALU（op 选择：加/减/与/或/异或/取反/直通）

### 6.5 存储（时序）
D 触发器（enable / async reset 可选引脚）、参数化寄存器、计数器（enable / reset / 可预置）、RAM（参数化深度×宽度，可编辑初始内容）、ROM（hex/bin 文件加载初始内容）、Stack（可选）

### 6.6 虚拟外设（半专业特色）
| 组件 | 说明 |
|---|---|
| Display | ASCII 字符网格屏（byte + draw 信号） |
| Keyboard | 输出按键 ASCII，valid 为 1-tick 脉冲 |
| 7 段数码管 | 4 位一组，BCD 或 7 段码输入 |
| UART | 可配波特率（按 tick 数），TX/RX，接虚拟串口终端 |
| 虚拟串口终端 | 打印字符、可回传输入 |

> 外设组件的 Verilog 导出映射见 ADR-24。

### 6.7 辅助元素（无电气行为）
| 元素 | 说明 |
|---|---|
| 文本注释 | 自由文本贴图，随 Board 保存；教学软件刚需 |

## 7. 封装与层次化设计

- 任意 Board → "另存为组件"：自动生成外观（或用户绘制简化符号）、引脚由 Board 边界上的输入/输出 Pin 推导。
- 组件库内可建文件夹分组；组件可在实例上"进入内部"修改（改动反映到所有实例）。
- 封装深度无限制，保存时做自引用环检测。
- 工程整体可导出/导入为自包含 JSON（含自定义组件定义）。

## 8. 编辑器

**基础操作**：网格吸附拖放、旋转（R）、框选、复制/粘贴/删除、**撤销/重做（栈式，必做，实现见 ADR-9）**、缩放平移、文本注释元素插入与编辑。

**连线**：点 Pin 拉线，正交 + 45° 折线；点击既有导线可分叉（T 型连接）；拖动整线或单段。**连接规则见 §4 Wire / ADR-7**：接触即连接、交叉不连接、junction 显式渲染。

**Net Label（网络标签，专业必需）**：给 Net 命名，同名即相连、无需物理连线。大电路（CPU 级）没有这个没法读图。

**调试**：
- 悬停探针：任意 Net 实时显示值（1 位 0/1，多位 hex/dec，可切符号性），**支持进入组件内部看子层 Net（ADR-25）**
- 点击组件/Net 可"加入波形观察"（见 §9.1）
- 全局导线值视图：默认关闭（千元件以上全屏标值又卡又乱），作为调试模式开关

**导线渲染状态**：灰=0，绿=1，彩色粗线=多位（值可选标注在线上），黄=悬空/未定义，红=冲突。

**DRC 交互**：错误列表窗口，**双击条目定位并高亮到具体组件/Net**（ADR-25 同款路径）。

**保存**：工程级 JSON，可 diff、可版本管理；保存写 `.tmp` 后原子替换，大工程异步保存防卡帧。

**Godot 渲染建议（不钉死，给方向）**：Board 为单个自定义 Control，`_draw()` 画网格与导线；组件为子节点，旋转交给 Node2D 变换；导线只在值变化时重绘对应区域（脏事件驱动 queue_redraw）；波形查看器自绘 Control，不依赖图表插件。

## 9. 专业化增强（P0 —— 没有这些就不叫半专业）

### 9.1 波形查看器 + VCD 导出
- 仿真时记录被观察 Net 的每 tick 值（环形缓冲，默认 10000 tick/通道，可配；VCD 导出 = 缓冲内容 + 测试台输入）。
- 时间轴 UI：多通道波形、双游标量延迟（"这个信号比那个晚 3 tick"一键测出）、缩放、跳转到边沿；**多 bit 通道按总线显示值（hex）**。
- **VCD 导出**：标准 Value Change Dump 格式，时间基准 1 tick = 1 ns（ADR-18），直接进 GTKWave / PulseView 等工具；**信号名用层级路径**（ADR-25）。
- 仿真 checkpoint（见 §9.7）不影响缓冲——checkpoint 恢复后缓冲从恢复点继续。

### 9.2 结构化 Verilog 导出
- 任意电路（含用户封装组件）一键导出 `.v`：
  - 用户组件 → Verilog module（递归展开或保持层次，可选）
  - 组合逻辑 → assign 语句
  - 时序元件 → `always @(posedge clk)`；RAM → reg 数组 + `initial $readmemh(...)` 加载初始内容
  - 顶层引脚 ← Board 边界 Pin；实例名 ← ComponentInstance.display_name（ADR-27 sanitize）
- **单时钟约束（ADR-20）**：导出要求电路仅含一个 Clock 实例，否则 DRC 报错阻止导出；Clock 组件映射为顶层输入端口 `clk`。
- **虚拟外设导出（ADR-24）**：Display/Keyboard/UART/数码管 等映射为**顶层 black-box 端口模块**（厂商 neutral 端口列表），导出时注释标明"此处接真机引脚或替换为你的外设模块"——不静默丢弃，不让用户误以为导出结果"少了什么"。
- **语义映射说明（写进导出注释）**：游戏内"1 tick 门延迟"是仿真可视化手段；导出的 Verilog 是常规零延迟组合逻辑 + 时钟沿同步语义，**周期级等价，而非 tick 级等价**。
- 验收：导出文件在 iverilog 仿真通过、Yosys 综合通过。
- VHDL 导出（P2，复用同一套网表遍历器）。

### 9.3 测试台框架（取代 TC 的关卡验证器）
- 用户自建测试向量：CSV / 表格编辑，格式 = 每行一个 tick：`驱动 pin 名:值, …, 期望输出名:值, …`（期望列可留空表示不检查）。
- 驱动范围（ADR-26）：**只驱动顶层 Board 的输入 pin**（包括把某个 pin 当 clock 用，此时板上通常不挂内置 Clock 组件以免混淆）；内置 Clock 组件在测试台运行时照常工作。
- 断言范围：**顶层输出 pin + 任意层级 Net**（路径 ADR-25），测试台可对内部寄存器写"期望"。
- 一键运行：置输入 → 跑指定 tick 数 → 逐 tick 比对期望 → 出差异报告（第一条失配：tick N，期望 X 实际 Y，定位到 Net）。
- 支持随机模式：约束随机 N 组（边界值全 0 / 全 1 / 0x55 / 0xAA / 单 bit 热码自动加入）；**随机种子显式记录在测试配置里**（ADR-16），保证可复现。
- 测试向量随工程保存；CLI 可 headless 跑全部测试向量（CI 用），报告同时输出人可读文本和 JSON（ADR-26）。

### 9.4 位宽参数化 + 符号数（影响数据模型，最先做）
- 位宽 {1,4,8,16,32} 贯穿组件/网络/探针/波形。
- signed/unsigned 作为 Net 显示属性 + 比较/ALU 语义开关。

### 9.5 DRC + 关键路径报告
- 检查项：组合环（反馈必须经过时序元件）、多驱动、悬空输入（警告）、位宽不匹配、门控时钟（警告）、多 Clock 实例（仅导出时报错）。
- 关键路径分析：最长组合逻辑路径（按 tick 计延迟，= 用户组件的涌现延迟），报告列出路径上的组件序列。
- 错误列表 UI 双击定位到具体组件/Net（§8）。
- **架构注意：DRC 必须先于 Verilog 导出实现**——可综合电路的约束（无组合环、时钟规范）要早一天定进数据模型，导出器就少一天痛苦。别把导出留到最后当附加功能写。

### 9.6 性能（并入引擎指标）
万级元件 < 5ms/tick，见 §5.1；criterion 基准测试进 CI（§14）。

### 9.7 仿真 checkpoint（v4 新增，进 M3）
- 任意时刻可保存当前仿真完整状态（全部组件内部状态 + tick 计数）为快照文件，之后可从快照恢复继续跑，等价于从该 tick 重新快进。
- 依赖 ADR-8 确定性：恢复后同一输入序列结果逐 tick 一致（checkpoint 是"可等价重演"的验证器，也是长程序调试的生产力武器：一次跑到位，之后反复从中间点探索）。
- 波形缓冲从恢复点继续追加，不重复记录。

## 11. 造机玩法：自建 CPU + 自定义指令集 + 汇编器（沙盒内的可选深水区）

TC 沙盒最迷人的部分保留：用户可以用 §6 的组件搭出自己的 CPU，然后**自定义指令集并汇编编程**。

### 11.1 指令集定义（JSON，工程内文件）
```json
{
  "schema_version": 1,
  "instruction_size": 8,
  "instructions": {
    "add":  { "binary": "0000", "args": ["reg", "reg"] },
    "addi": { "binary": "0001", "args": ["reg", "imm6"] },
    "jmp":  { "binary": "1100", "args": ["addr6"] },
    "movc": { "binary": "1101", "args": ["cond", "addr6"] }
  },
  "arg_types": {
    "reg":  { "R0":"0000", "R1":"0001", "…": "…" },
    "cond": { "always":"000", "EQ":"001", "LT":"010", "LTU":"011" },
    "imm6": { "type":"int", "bits": 6 },
    "addr6":{ "type":"uint", "bits": 6 }
  }
}
```
- 指令字默认 8 位，可扩展双字（立即数 > 剩余位宽时）。
- opcode 占 log2(指令数) 位，余位分配给操作数；分不够报错并提示建议双字。

### 11.2 汇编语法
- 一行一条指令；`label:` 定义标号；`;` / `#` 注释。
- `const NAME val`（有符号）/ `uconst NAME val`（无符号）；数字支持十进制 / 0x / 0b。
- 标号可作 addr / imm 操作数（取其地址）。
- 输出：字节流（可显示为 hex），UI 一键"烧入选中 ROM 组件"（M5）。

```asm
start:
    addi R1 R1 5      ; R1 += 5
    movc EQ done      ; 条件跳转示例
    jmp  start
done:
    …
```

### 11.3 参考架构（给用户的自建 CPU 骨架，文档内置教程，非关卡）
- 程序 ROM（256×8）+ PC（寄存器 + 加一器 + load 使能）
- 指令寄存器 IR：时钟上升沿锁存 ROM[PC]
- 15 个通用寄存器（4 位地址译码）+ 常量 0
- ALU：加/减/与/或/异或/取反/直通，操作码选择
- 标志位：EQ / LT（有符号）/ LTU（无符号）
- 译码逻辑：opcode → 寄存器写使能 / ALU op / RAM we / PC load / 条件使能
- 每指令 1~2 个时钟周期；CPU 时钟周期必须 > 数据通路最长组合延迟（用户组件涌现延迟 §4）

## 12. ADR 决策记录（所有模糊点一锤定音）

| # | 问题 | 决策 | 理由 |
|---|---|---|---|
| 1 | 时序组件输出延迟 | **一律 1 tick**（含触发器：沿在 t 被看到，输出 t+1 出现） | 一致性 > 逼真度；TC 同款；用户心智模型只有一条规则 |
| 2 | 上电状态 | 全 0；RAM preload | 确定性要求；需要非零初值用 preload |
| 3 | 复位语义 | async reset 优先于时钟锁存，下一 tick 生效 | tick 模型下"异步"= 不等沿；不做真异步 |
| 4 | 算术溢出 | wrap 补码回绕 | 硬件标准行为 |
| 5 | 部分位无驱动 | 位 = 0 | "悬空即 0"位级推广 |
| 6 | 位宽混接 | 禁止，DRC 拦截，必须 Splitter/Merger | 隐式拆合语义模糊，是 bug 之源 |
| 7 | 连线连接判定 | 端点落在另一条线上/线端 = 连接；**纯交叉不连接**；junction 实心圆渲染 | 专业工具惯例；避免"为什么这两根线连上了" |
| 8 | 确定性 | 同输入时间表 → 逐 tick 可复现；实例遍历顺序无关 | 回归测试与"确定性"承诺的前提 |
| 9 | 撤销/重做归属 | **core 内命令模式**（命令对象可反演），UI 只发命令；初始态 + 命令流可重建 | 换壳时编辑历史不丢；可测试 |
| 10 | 仿真循环位置 | M1~M2：Godot `_process` 累加器；超速/长程序：core `run_for(n)` 工作线程快进 | 分阶段复杂度；UI 与仿真解耦 |
| 11 | 工程文件 | 单 JSON 自包含（含自定义组件/测试向量/波形配置）；`schema_version` + 链式迁移 | 可 diff 可版本管理；全局用户库为可选独立目录，M5 后再说 |
| 12 | 用户组件覆盖官方 | 工程内定义优先，导出以工程为准 | 用户自定义不被官方库升级破坏 |
| 13 | 版本与工具链 | 稳定版 Rust（MSRV 写进 Cargo.toml）；Godot 4.x + gdext，**版本锁死**（CI 编译矩阵验证） | gdext 对 Godot 小版本敏感 |
| 14 | RAM 初始内容 | 工程内嵌 hex 字符串 + hex/bin 文件导入 | 自包含与便利兼得 |
| 15 | 波形缓冲 | 环形 10000 tick/通道，可配；VCD 导出 = 缓冲内容 + 测试台输入 | 防内存爆炸；说明写进 UI |
| 16 | 测试随机模式 | 种子显式记录在测试配置 | 可复现 |
| 17 | tick 与帧的关系 | 1 tick = 1 仿真步，与 Godot 帧/物理帧完全无关；调速 = 每帧执行 tick 数 | 见 ADR-10 累加器 |
| 18 | VCD 时间基准 | 1 tick = 1 ns | VCD 格式要求 timebase，定死避免每次导出不同 |
| 19 | 多时钟域 | 允许多 Clock；门控时钟警告不报错；不做 CDC 检查 | TC 同款玩法空间；专业检查放 P2 |
| 20 | Verilog 导出时钟映射 | **单 Clock 约束**：>1 个 Clock 实例 → DRC 报错阻止导出；Clock → 顶层端口 `clk` | 可综合性硬约束 |
| 21 | core 的 IO 边界 | core 不碰文件系统/时钟/UI：JSON 用 `&str`/`&[u8]` 进出，tick 由外部驱动 | 脱离 Godot 的保证（§3.4） |
| 22 | 浮点使用 | 逻辑层全整数（格坐标、值、tick）；浮点只存在于渲染层 | 确定性与精度 |
| 23 | 编辑与仿真关系 | **任何编辑命令（含 undo/redo）生效 → 仿真状态重置上电态、清空波形缓冲**；编辑不强制暂停 | 否则 undo 后寄存器值 undefined，实现者必然踩坑 |
| 24 | 虚拟外设的 Verilog 导出 | Display/Keyboard/UART/数码管 → 顶层 **black-box 端口模块**，注释"此处接真机引脚或替换为你的模块"；RAM preload → `initial $readmemh` | 不静默丢失功能；上板衔接点 |
| 25 | 层级调试 | 探针/波形/测试断言/VCD 信号名支持**层级路径** `board/instance/…/net`，实例默认名 inst_<n> 可改 | TC 只能进组件看，半专业必须能"从外面看里面" |
| 26 | 测试台驱动规则 | 只驱动顶层输入 pin（含把 pin 当 clock）；内置 Clock 组件照常工作；报告同时出人可读 + JSON | 模型简单无歧义；CI 友好 |
| 27 | Verilog 导出命名 | 实例/模块名 sanitize：非 ASCII 与非法字符替换 `_`、Verilog 保留字避让、重名追加 `_n` | 用户组件叫"我的加法器"必须能导出 |
| 28 | 用户组件延迟属性 | **无独立 delay 字段**，= 内部最长组合路径（涌现值，引擎推导）；内置组件恒 1 tick | v3 数据模型缺陷修正；关键路径报告依此计算 |

## 13. 里程碑（迭代路线，每个有退出标准）

> 原则：先架构后功能，每步可验收，架构层（core/壳分离、语义钉死）在 M0 一次定死，后面只加功能不动骨架。

**M0 —— 纯 Rust 核心（无 UI，1~2 周量级）**
- 范围：core 数据模型（参数化位宽/符号属性/涌现延迟）、tick 引擎（双缓冲 + prev_tick 边沿 + 脏标记）、netlist 推导、JSON 序列化 round-trip、命令栈 undo/redo、基础组件（门/常量/开关/D 触发器/寄存器/RAM/Clock）、cli 雏形（headless 跑电路）
- 退出标准：`cargo test` 全绿——含 NAND 搭加法器逐 tick 断言、SR 锁存器行为、确定性不变量测试（§14）；cli 跑 1000 tick 输出文本波形

**M1 —— Godot 最小壳**
- 范围：GDExtension 集成、放组件/拉线/删除/旋转/undo、导线状态渲染、探针、累加器调速（暂停/单步/1~60 tick/s）、文本注释
- 退出标准：在 UI 里搭出 SR 锁存器并看到自锁行为；搭环形振荡器看到逐 tick 涟漪；保存/重开工程不丢；编辑后仿真按 ADR-23 重置

**M2 —— 完整编辑器 + 全组件库**
- 范围：§6 全组件、封装（嵌套 + 环检测）、net label、多 Board、DRC 基础项（多驱动/位宽/悬空/组合环 + 定位 UI）、性能基准达万元件 <5ms/tick
- 退出标准：能用封装组件搭 8 位 CPU 数据通路（PC+ROM+寄存器堆+ALU）并单步观察；DRC 双击定位生效

**M3 —— 专业四件套 + checkpoint**
- 范围：波形 UI + 双游标 + VCD 导出（层级命名）、测试台（CSV + 随机模式 + 层级断言）、CLI headless 回归（JSON 报告）、关键路径报告、**仿真 checkpoint（§9.7）**
- 退出标准：给一个时序 bug 电路，用双游标量出延迟差并定位；CLI 跑全工程测试向量出 JSON；checkpoint 恢复后与连续运行的波形逐 tick 一致

**M4 —— Verilog 导出**
- 范围：导出器（含用户组件递归展开、命名 sanitize、外设 black-box 映射、RAM $readmemh）、单时钟 DRC 约束、导出注释带语义说明
- 退出标准：M2 的 CPU 电路导出后 **iverilog 仿真 + Yosys 综合双通过**，且综合结果行为与 core 仿真周期等价（对比测试向量输出）

**M5 —— 造机与外设**
- 范围：Display/Keyboard/数码管/UART、汇编器 + ISA JSON + CLI、ROM 一键烧录、参考 CPU 教程文档
- 退出标准：自建 CPU 跑通含条件跳转 + UART 输出的真实程序

**M6+**：P1/P2 按需排期（FSM、三态、SVG、Yosys 报告、引脚绑定、VHDL）。

## 14. 测试与 CI 策略

**core 单元测试（每个组件一张语义表）**：
- 组合件：全输入穷举（位宽小）/ 边界+随机（位宽大）
- 时序件：给定输入序列 + 时钟序列，逐 tick 断言输出

**不变量测试（架构的保险丝）**：
- 确定性：同一电路同一输入序列跑两遍，波形记录逐 tick 相等
- 顺序无关：打乱 instances 数组顺序（netlist 不变），结果逐 tick 相等
- 序列化 round-trip：load→save→load，JSON 完全一致
- undo/redo：随机命令序列 + 全量 undo 回到初始态序列化相等
- checkpoint 等价（M3 起）：从 checkpoint 恢复继续跑 N tick ≡ 连续运行 N tick

**golden 文件测试**：固定电路 + 固定输入 → 波形 hash 入库，防语义漂移（改引擎必跑）

**性能基准**：criterion，万元件电路（加法器树 + 寄存器阵列）tick 耗时，CI 报告

**CI（GitHub Actions）**：
- 每个 PR：`cargo fmt --check` + `clippy -D warnings` + `cargo test`（core/cli 不依赖 Godot，直接跑）
- godot-shell 编译矩阵：Rust stable + 锁定的 Godot 版本
- M3 起：CLI 跑示例工程测试向量
- M4 起：容器里 iverilog + Yosys，自动验证导出件（验收线自动化）

## 15. 验收标准（"勉强能当半专业软件"的判定线）

1. 用它搭一个 8 位 CPU + UART，跑通一段含条件跳转的真实程序
2. 任意电路导出 Verilog：**iverilog 仿真 + Yosys 综合双双通过**（游戏与工具的分水岭）
3. 用户能自建测试向量做回归，失配报告能定位到 Net 和 tick
4. 出 bug 时能用波形查看器量出"哪条 Net 哪个 tick 出的问题"
5. 万级元件工程仿真每 tick < 5ms
6. （架构验收）`cargo check -p core -p cli` 在无 Godot 环境编译通过——core 可独立存活
7. （新增）checkpoint 恢复后行为与连续运行逐 tick 一致

## 16. 关键坑位提醒

- 边沿触发必须用 prev_tick 快照实现，不能在 eval 里就地改状态（否则双缓冲失效、结果不确定）
- 多驱动必须在编辑期拦截，不能等仿真期报错
- 嵌套组件保存要做自身引用可达性检查，否则无限递归
- Verilog 导出前必须先过 DRC（组合环导出去也综合不过）
- 事件驱动优化别破坏确定性（ADR-8 的不变量测试兜底）
- **godot 类型一旦泄进 core，"脱离 Godot"即告废**——CI 用 core 单独编译来强制
- gdext 与 Godot 小版本兼容性：锁版本，CI 矩阵验证，升级 Godot 是显式决策不是顺手升级
- 累加器放 `_process`，别用物理帧；`max_ticks_per_frame` 防低帧率雪崩
- 大工程 JSON 保存：异步线程写 + `.tmp` 原子替换，别卡 UI
- 逻辑层禁浮点（ADR-22），坐标/值/tick 全整数，浮点只进渲染层
- **用户组件延迟是涌现值，别缓存成字段**：内部一改就过期，每次构建 netlist 重推
- 编辑生效重置仿真（ADR-23）：**波形缓冲也要清**，否则用户会拿着旧波形 debug 新电路
